# Private stat-api Research Desk

This Pro integration is for **one CrownIQ owner's personal research**. The private watchlist/notebook itself does not publish to the public board, tracked decisions, Social, or result grading. Ordinary mobile refresh never uses it. Separately, the server can opt into `GKR_STAT_EVIDENCE=true`, which reuses the same licensed Stat API client to build attributed historical distributions and directly derivable numerical factor evidence for supported NFL/NBA/MLB markets. That adapter never publishes owner notes and never fabricates lineup, injury, weather, opponent, or role status. No notebook schedule runs until the owner explicitly watches a player table.

## Set up securely

1. Create or sign into your CrownIQ profile. In Settings, copy **Your profile ID** (a UUID, distinct from your display name and email).
2. Set `CROWNIQ_OWNER_PUBLIC_ID` to that UUID in the **CrownIQ API server environment**.
3. Rotate any Pro key that has appeared in a message or screenshot. Put the new key in the server secret environment as `STAT_API_KEY`. Never commit it, paste it into Expo, or use an `EXPO_PUBLIC_*` variable. Restart the backend after setting both variables.
4. Mount a protected persistent volume for `CROWNIQ_OWNER_RESEARCH_FILE` (default `tmp/owner-stat-research.json`). The JSON file is Git ignored, written atomically with mode `0600`, and holds watched samples and owner notes. Do not place it on public storage.
5. `CROWNIQ_OWNER_RESEARCH_REFRESH_MINUTES` defaults to 60 (allowed 15–1440). `CROWNIQ_STAT_API_DAILY_RECORD_LIMIT` defaults to 100,000 rows (maximum 500,000). The in-process daily ceiling and cache reset when the server restarts. For a strict account-wide budget across restarts/replicas, add durable shared reservations. The vendor's 20 million Pro records/month and monthly 429 are the definitive limits; its pricing FAQ says no automatic overage billing.

Settings shows **Owner Research Desk** only for that signed-in profile. Every owner route independently checks the authenticated server session and returns 404 to other users. With no configured UUID, nobody can access it. With no key, the owner sees setup help and zero provider calls. The mobile bundle never receives the provider key or `ADMIN_TOKEN`.

## Coverage and usage

- Live player research: **NFL, NBA, MLB and PGA**. NHL endpoints are documented but currently return 503 pending production data. DFS is cross-league data, not another player sport. No live vendor coverage is documented here for WNBA, soccer, tennis, esports, or college sports; CrownIQ retains its existing sources for those.
- Owner search (`GET /v1/owner/research/search?sport=PGA&q=...`) uses the documented NBA name search or a cached bounded player page for the other sports. NFL/MLB page up to 2,500 active roster rows; PGA scans up to 2,500 players. If the vendor reports more rows, `partial` is true. Owner selects a provider player ID; identity is never guessed from PrizePicks names.
- Player inspection (`GET /v1/owner/research/player/:sport/:id?table=...`) verifies the player ID and returns at most 40 mapped stat rows per supported table, with source URL and retrieval time. The table choices are NFL/NBA game player stats, MLB batter/pitcher game stats, and PGA player rounds/season stats. The API's page order varies; the UI calls them **returned rows**, never verified L10 or a projection. Official lineup, role, and event confirmation remain independent.
- **Watch and auto refresh** (`POST /v1/owner/research/watch`) saves one selected player/table and activates server-side hourly refresh. Maximum 100 saved entries; entries run sequentially, stop on provider/budget 429, and retain their previous snapshot when a request fails. New observations clear the reviewed flag. Empty watchlists, non-owner visitors, and ordinary board reads generate zero stat-api calls. **Stop watching** archives the saved entry. Manual `POST /v1/owner/research/refresh` requires `acknowledgeRecords:true` and starts a separate background job; it does not refresh PrizePicks odds. The timer stops with the server.
- `GET /v1/owner/research/status` shows local row use, observed monthly quota headers, and notebook refresh state without calling the provider. Results and searches use short-lived caches, fixed provider host/allowlisted tables, nine-second timeouts, response-size caps, in-flight deduplication, and no automatic retries. All owner responses specify `Cache-Control: private, no-store`.

## Private file and editing

The server keeps `CROWNIQ_OWNER_RESEARCH_FILE`. `GET /v1/owner/research/export` returns the **collected notebook**, with fetched samples, source URLs, timestamps, review status, notes and independent HTTPS sources. It does not bulk export the vendor's database. The iPhone Research Desk can offer a JSON file to the iOS share sheet for a private save; the web app downloads the JSON. Android can use the CrownIQ web app for downloads. Notes are also editable directly on mobile.

Edit only each entry's `notes`, `independentSources` (up to five HTTPS URLs), and `reviewed`. **Import edited notes** calls `PUT /v1/owner/research/import` with the JSON file. The importer accepts existing entry keys, validates owner annotations, rejects a stale file that tries to mark newer research reviewed, and **ignores edits to provider metrics, identifiers, source URLs, and timestamps**; it returns `providerSnapshotsChanged:false` and `gkrEvidenceCreated:false`. An owner can annotate a questionable stat or link to an independently licensed correction without rewriting the original observation. Large files are rejected by the app and API. Keep exported files private.

The September 26, 2026 [vendor terms](https://stat-api.com/terms/) permit personal Pro caching and modeling but prohibit other users accessing **any output relying on the data** without a separate written Enterprise license. [Pricing](https://stat-api.com/pricing/) expressly says this applies even to derivative work. Editing provider-derived data or adding notes does not bypass this rule. Accordingly, no import route enters the public GKR research registry. Before licensing provider-backed public outputs, obtain written rights and design a separately reviewed, attributed, versioned GKR adapter. Independently licensed evidence may use CrownIQ's existing research processes. The provider also disclaims being an official grading record.

Tests use fake responses and make **no paid stat-api requests**. Live use still requires a deployed backend with a rotated server key and your signed-in owner profile UUID.
